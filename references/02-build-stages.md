# 02 · 分阶段施工与验收

## 两类状态不可混用

`BUILD_STATE.json` 表示这套工作流搭到哪一步。
`tasks/<id>/state.json` 表示某一项工作执行到哪一步。
S3 创建了目录，不意味着 S4 试点通过；运行环境能启动，不意味着任务 DONE。

| 阶段 | Agent 的动作 | 人的动作 | 产物与放行检查 |
|---|---|---|---|
| S0 | 读已有对话、指定文件和构建状态；在范围内检查读写、执行、验证能力 | 只补真正缺失的信息 | 能力分为 VERIFIED / UNKNOWN / UNSUPPORTED / HUMAN；记录证据 |
| S1 | 将自然语言改写为小任务；写非目标、输入、交付边界、验收 | 确认目标、允许的资料和范围 | 每个必选验收项有可观察判据；草稿与外部动作分开 |
| S2 | 设计最小方案；列变更、依赖、账户、数据去向、成本、停止和恢复方式 | 确认实施范围或保持规划模式 | 保存真实批准引用；没有批准不修改用户环境 |
| S3 | 只在新工作区创建模板；记录实际能力；只读检查一致性 | 仅做本人登录等不可代办动作 | 不覆盖旧配置；不把模板状态填成已验证 |
| S4 | 用获准输入执行一项任务；提交候选版；逐项检查 | 验收或指定独立检查者 | 产物存在，来源可定位；未知信息不补造；交付版本与验收一致 |
| S5 | 在检查点换会话或工具；验证恢复；需要时再设计一个自动入口 | 决定是否值得增加自动化 | 无重复副作用；不扩大数据外发和权限；未选自动化可跳过该扩展 |
| S6 | 整理使用说明、未完成项、停止和恢复说明 | 确认知道在哪里看结果、待决事项、停止入口 | 当前约定层级通过；指出没有部署的能力 |

## 最小实现选择

| 层级 | 优先使用 | 明确不需要 |
|---|---|---|
| M0 人工闭环 | 聊天 + Markdown；用户保存、授权和验收 | 后台进程、数据库、多个模型 |
| M1 本地辅助 | 一个工作区 + 文件操作 + 可重复检查 | 外部机器人、无人值守队列 |
| M2 有界自动化 | 一个事件入口 + 受控状态/队列 + 能力适配 + 真实权限控制 | 全平台监听、多个入口同时上线 |

默认到 M0 或 M1 即可交付。S5 的恢复演练必须做；M2 扩展不是必经步骤。
前一阶段失败，修复失败项，不自动安装更多组件解决流程不清的问题。

## 第一轮试点

包内 `assets/workspace/tasks/T-DEMO-001/inputs/` 是虚构资料，不是实测数据。
最初的合同和状态都是 DRAFT。Agent 必须让人确认范围，然后实际生成结果并检查。
校验器只查记录结构；业务验收者仍需回到输入核实每一项结论。

完成本地试点后，再补一条失败路径和一次恢复：
- 故意缺少一个必要输入，应该清晰阻塞或交付带缺口的许可范围结果。
- 新会话只读交接，必须能说清下一步、禁区、余量和未知外部效果。

## 升级门槛

进入 M2 前，完成场景测试：未授权触发、重复事件、超时、撤权、取消、预算耗尽、版本变化和输入注入。
自动化任务、服务安装和外部数据读取另行批准。没有测过停止能力，不开无人值守。
指标先记录基线：人工决定次数、首次验收、越权尝试、重复副作用、恢复结果；不声称某通过率代表安全认证。
