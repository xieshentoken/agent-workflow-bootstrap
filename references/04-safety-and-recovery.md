# 04 · 安全、排错与恢复

## 禁止偷换概念

| 不能说成等价 | 正确区别 |
|---|---|
| 获准接单 = 获准执行一切 | 还要核对每项动作、数据与外部影响 |
| 独立目录 = 沙箱 | 目录是组织方式，隔离须由系统权限和执行环境验证 |
| paused = 已停止 | 暂停可能只停止派单；运行中进程和在途请求另查 |
| report ready = 验收通过 | 候选结果仍要按合同检查 |
| 脚本 PASS = 业务正确 | 局部一致性检查不能判断报告是否真实 |
| 模型共识 = 证据 | 应核实输入、计算、测试或外部状态 |
| 重启 = 恢复成功 | 还须排除重复副作用和失效授权 |

## 四种停止动作

暂停入口：不再接新事件。暂停派单：记录但不启动新执行。
停止当前任务：请求终止可控进程，核对在途副作用。撤销授权：阻止新的受限动作，并按实际系统收回能力。
发生不可逆效果时，清楚记录已发生的事实，必要的补偿另行授权。不能声称“停止即回滚”。

规则收紧或授权撤销后，本设计要求在下一个受限动作前重新检查并阻止新影响。
运行中动作能否打断取决于工具，要报告“已停止 / 停止请求已发出 / 未能核实”，不能混用。

## 排错树

| 现象 | 优先检查 | 允许处理 |
|---|---|---|
| 没有产物 | 工具是否真的执行、输出路径、权限、失败记录 | 小范围重试；不能伪造文件存在 |
| 登录失败 | 指定身份、凭据是否到期、目标资源授权 | 由用户在安全界面登录；不索要 token |
| 工作区已存在 | BUILD_STATE、上一版计划、哪些是用户自有文件 | 提出合并或迁移差异；不 --force |
| 记录显示完成但产物变化 | 版本与哈希、原验收证据 | 重新验收，不沿用旧 PASS |
| 外部发送超时 | 外部回执、查询记录、业务唯一标识 | UNKNOWN；查清前不重新发送 |
| 模型限额耗尽 | 剩余预算、当前检查点 | 暂停；换模型须复查数据去向 |
| 启动后不断接任务 | 准入、去重、机器人回声、入口模式 | 暂停入口和派单；不靠增加通知解释 |
| 用户要求停 | 各执行器、子任务、在途操作、权限 | 阻止新动作，尽力停止并核实 |

## 恢复包

保存：合同版本、当前状态、原 run_id、已完成产物、核实事实、未知项、已执行/UNKNOWN 的外部动作、有效授权、剩余预算、待决问题、一个下一步。
新执行者必须先确认原执行停止和能力适配，再恢复。跨模型迁移还要核对敏感数据的处理位置。
不要要求保存模型的私有推理链，只保存可审查的依据和操作记录。

## 辅助脚本的边界

脚手架仅给模板目录创建提供防误覆盖检查，不提供多用户安全和竞态下的沙箱。
校验器读取指定工作区的记录，检查少量字段、引用和产物哈希；不验证授权真实性，不运行任务。
同一系统用户能改文件时，文件内容不是可信的不可篡改审计。进入 M2 前需要真正独立的控制面。
